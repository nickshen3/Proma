# 会话进程面板（Session Process Panel）需求文档

- 日期：2026-08-27
- 状态：草案（待评审）
- 分支：`my-proma`（本功能为定制开发，不属于上游功能）
- 关联上游背景：旧版 `BackgroundTasksPanel` 已于上游 #1789（2026-08-23）作为死代码移除，本功能基于 Pi runtime 架构重新设计，与其无代码继承关系。

## 1. 背景与问题

Agent 在会话中执行命令时，存在两类真实的进程形态，但都缺乏统一的可观测入口：

1. **命令进程**：Agent 通过 bash 等命令工具执行的命令。短命令执行完即退出；长驻进程（dev server、watcher、端口占用程序）启动后，UI 上仅表现为消息流中一个持续"进行中"的过程块，用户无法确认它是否还活着、占用什么资源，也没有入口去终止它——只能让它超时或在消息流中干预。
2. **终端**：Agent 帮用户打开的终端以独立 tab（`terminal:{id}`）散落在右侧工作区，没有"这个会话一共开了哪些终端"的总览。

本功能在右侧工作区新增一个**会话进程面板**，聚合展示当前会话打开的全部进程（命令进程 + 终端），支持监控与终止。

## 2. 目标与非目标

### 目标

- G1：一个聚合 tab 内总览当前会话的全部进程（命令进程 + 终端），实时反映状态。
- G2：支持查看进程详情与实时输出流；终端可跳转到其独立终端 tab。
- G3：支持终止单个进程。
- G4：进程退出后保留记录（退出码、输出历史），可按"活跃 / 全部"筛选。
- G5：按会话隔离，切换会话时面板跟随展示对应会话的进程。

### 非目标（本期明确不做）

- N1：向进程 stdin 发送交互输入（如回答交互式提示）。依赖 PTY 级接入，成本高、场景少。
- N2：输出内容搜索、复制全部输出等输出辅助操作的完整实现（复制单条输出可在后续版本补充）。
- N3：跨会话的全局进程视图。面板严格按会话隔离；全局视图作为未来扩展方向。
- N4：进程资源占用监控（CPU / 内存）。上游无对应数据源，列为远期候选。
- N5：不影响也不改造 Agent bash 工具本身的执行模型（同步执行、超时策略等维持上游行为）。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 命令进程 | Agent 在会话中通过命令执行类工具（bash 等）启动的 OS 进程及对应的命令执行记录 |
| 终端 | 通过 `terminal-service` 创建的 node-pty 终端实例，已有独立 tab 展示 |
| 进程记录 | 面板中的一条条目，包含命令、来源、状态、起止时间、退出码、输出 |
| 活跃进程 | 状态为 running 的进程记录 |

## 4. 用户故事

- US1：作为用户，我让 Agent 启动 dev server 后，打开右侧「进程」tab，能看到它处于 running、已运行时长和实时日志，确认它真的起来了。
- US2：作为用户，dev server 卡住时，我在进程面板点击「终止」，进程被杀掉，消息流中对应的工具执行同步结束。
- US3：作为用户，我切换到另一个会话再切回来，进程面板展示的始终是当前会话的进程，互不串扰。
- US4：作为用户，一个命令退出后，我在"全部"筛选下仍能看到它，带退出码，回看它的输出历史，排查"刚才那个命令为什么失败"。
- US5：作为用户，Agent 帮我开了 3 个终端，我在进程面板一眼看到全部终端及其状态，点击任一项可跳到对应的独立终端 tab。

## 5. 功能需求

### 5.1 进程登记

- FR1.1 系统自动登记当前会话产生的两类进程记录：命令进程、终端。无需用户手动添加。
- FR1.2 命令进程在命令开始执行时登记；终端在创建时登记。
- FR1.3 每条记录包含：显示名（命令摘要或终端标题）、来源图标（命令 / 终端）、当前状态（running / exited / killed）、启动时间、运行时长、退出码（退出后）、输出流。
- FR1.4 终端类记录必须与现有终端 tab 数据同源（同一 terminalId），不允许出现两套并行状态。

### 5.2 聚合 tab 展示

- FR2.1 右侧工作区新增基础 tab「进程」（与 files 等基础 tab 同级），类型为聚合视图，不采用每进程一个 tab 的形态。
- FR2.2 tab 徽标显示活跃进程数量；无活跃进程时不显示徽标。
- FR2.3 有新进程启动时**不自动切换**到进程 tab（遵循"不抢用户当前视图"原则，与 `isUserPriorityWorkspaceComponentTab` 的设计精神一致），仅通过徽标提示。
- FR2.4 列表项展示：状态指示（颜色点 / 图标）、显示名、来源类型、运行时长（活跃时实时递增）或退出码（已退出）。
- FR2.5 列表按启动时间倒序（最新在上），活跃进程排序高于已退出进程。

### 5.3 进程详情与独立视图

- FR3.1 点击列表项在面板内展开该进程的输出区域（列表下方或侧边内嵌展开），滚动展示实时输出，支持暂停滚动。
- FR3.2 终端类记录的详情区提供「在终端 tab 中打开」入口，跳转到对应 `terminal:{id}` 独立 tab（若该 tab 已被用户关闭，按现有终端关闭语义处理并提示）。
- FR3.3 命令进程不提供独立 tab，统一在聚合视图内展开查看。

### 5.4 操作能力

- FR4.1 活跃进程提供「终止」操作（单项操作，本期不提供"全部终止"批量操作，降低误操作面）。
- FR4.2 终止终端 = 复用现有 `killTerminal` 链路；终止命令进程 = 触发该命令执行的中断（语义见 7.3 技术风险）。
- FR4.3 终止操作需二次确认（轻量确认，如按钮变为"确认终止?"二段式），避免误杀。
- FR4.4 已退出进程不提供终止操作，仅保留查看。
- FR4.5 只读监控能力：状态、运行时长、实时输出，不做任何修改进程状态之外的动作。

### 5.5 生命周期与筛选

- FR5.1 进程退出后记录保留在列表中，状态标记为 exited（正常退出，含退出码）或 killed（被用户终止），输出历史可回看。
- FR5.2 面板提供「活跃 / 全部」筛选，默认「活跃」。
- FR5.3 会话内记录在会话存续期间保留；会话删除时其进程记录一并清理（活跃进程应随会话删除被终止，见 FR5.4）。
- FR5.4 会话删除时，若仍有活跃进程（含终端），按现有会话清理行为终止它们（终端已有对应处理；命令进程跟随其执行中断）。
- FR5.5 进程记录仅在内存中维护，不持久化到磁盘（应用重启后历史输出不必恢复；活跃终端本身的持久化跟随现有终端能力，不因本功能改变）。

### 5.6 会话隔离

- FR6.1 进程数据按 sessionId 隔离存储（与 `agentTerminalTabsAtom` 的 Map 形态一致）。
- FR6.2 切换会话时，面板内容与徽标数量跟随切换。
- FR6.3 协作子会话（delegation / exploration）的进程归属其子会话自身，不出现在父会话面板中。

## 6. 交互与 UI 要求

- 空状态：无任何记录时展示引导性空状态（"此会话暂无进程，Agent 执行命令或打开终端后将显示在这里"）。
- 加载态：数据为同步内存读取，无需 loading；输出流区域首帧渲染前不闪屏。
- 键盘操作：列表支持上下键移动、Enter 展开详情、终止按钮可 Tab 聚焦。
- 主题：复用既有 Radix/shadcn primitives 与主题变量，深浅主题均需检查状态色可读性（running 绿 / exited 中性 / killed 警示色）。
- 窗口宽度：右侧面板在窄宽度下列表项优雅截断（命令摘要 ellipsis + title 悬浮全文）。

## 7. 技术方案概要

### 7.1 数据来源

- **终端**：完全复用 `terminal-service` 与 `agentTerminalTabsAtom` 现有数据，面板作为同一状态的另一个视图，不新增存储。
- **命令进程**：基于 Pi runtime 的工具调用事件流追踪。`AgentToolCallDelta`（`packages/shared/src/types/agent.ts`）已为每个工具调用提供稳定 `id`，`toolcall_start / toolcall_delta / toolcall_end` 事件齐全，进程记录以工具调用 id 为关联键；输出流复用现有 stream 转发链路（与 ProcessBlockGroup 的数据源一致）。
  - **登记时机**：在 `BashToolOptions.spawnHook`（见 `pi-agent-adapter.ts` 的 `createPromaBashToolOptions`）中登记即将 spawn 的命令（时间、命令、cwd），该 hook 已是 Proma 既有定制点。
  - **WSL 路径**：`createWslBashOperations` 由 Proma 完全自研 spawn，`child.pid` 与 `kill` 天然可得，可直接提供精准 PID 与终止。
  - **标准路径**：child 由 pi-coding-agent 内部 spawn，Proma 侧拿不到实例，终止走 V1 中断语义（见 7.3）。

### 7.2 IPC 与状态管理（四层契约）

新增 IPC 需同步四层（遵循项目规范）：

1. `packages/shared`：进程记录类型 `SessionProcessInfo`、通道常量（如 `agent:processes:list`、`agent:processes:kill`）与请求/响应类型、进程状态变更事件类型。
2. `apps/electron/src/main`：handler 实现与进程登记服务（命令进程登记 + 终止转发）。
3. `apps/electron/src/preload`：bridge 暴露。
4. renderer：Jotai atom（建议 `agentProcessesAtom: Map<sessionId, SessionProcessInfo[]>`）+ 面板 UI + `AgentSidePanelTab` 扩展（新增基础 tab `processes`）。

### 7.3 技术风险与降级方案（2026-08-27 spike 已验证）

Spike 结论（代码证据见 `apps/electron/src/main/lib/adapters/pi-agent-adapter.ts`）：

1. 工具调用 id 稳定可用：`AgentToolCallDelta.id` + `toolcall_start/end` 事件完整，进程记录关联键无歧义。
2. 中断链路已存在：adapter 有完整的 `abortRequested / interrupting` 状态机；Proma 自研的 `BashOperations.exec` 中 `options.signal` abort → `child.kill('SIGTERM')` 是现成模式。
3. WSL 路径 `child.pid` 直接可得；标准路径 child 由 pi 内部 spawn，Proma 侧不可达。

因此终止语义定为两层：

- **V1（默认，无 patch 依赖）**：终止 = 触发该工具调用 id 对应执行的 abort，复用现有中断状态机；登记用 `spawnHook`。满足"停掉卡住的长驻进程"核心诉求。UI 如实呈现「中断执行」。
- **V2（增强，可选后续）**：仿照现有 `pi-ai@0.84.2.patch` 先例，给 `pi-coding-agent` 打小 patch 暴露 child/pid（或向上游提 PR），实现精准 kill 与 PID 展示；WSL 路径无需 patch 即具备。

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 标准路径拿不到 PID | child 在 pi 内部 spawn | V1 中断语义兜底；PID 展示仅对 WSL 路径或 V2 生效，UI 对 PID 字段不做承诺 |
| 长驻命令与上游超时策略的交互 | 上游 bash 工具有自身超时/轮询行为，面板终止不能与之打架 | 终止统一走 runtime 中断接口，不复刻信号发送；`bun install` 后验证 dev server 长驻场景 |
| spawnHook 与 abort 的时序 | 登记早于 child 实际 spawn，极早退出的命令可能产生幽灵记录 | 工具执行结束事件负责收敛状态，幽灵记录以 exited 收尾，不影响力要路径 |

### 7.4 实现顺序建议

1. 终端聚合（数据现成，先打通面板骨架与筛选/详情交互）
2. 命令进程登记与只读展示（事件流接入）
3. 终止能力（含二段式确认）
4. 边界打磨（会话删除清理、窄宽度、键盘、深浅主题）

## 8. 边界场景

- 同一会话并发运行多个同命令进程：各自独立记录，以启动时间与调用 id 区分。
- 终端被用户在独立 tab 中手动关闭：聚合列表同步标记 killed/exited。
- 会话恢复（重启应用后继续会话）：进程记录不恢复（FR5.5），活跃终端跟随现有终端恢复行为。
- 右侧面板未打开时有新进程启动：徽标在面板 tab 上可见；面板本身不自动展开。
- 输出量极大的进程：输出区域使用与现有终端/日志一致的缓冲上限策略，滚动查看，不做无限增长。

## 9. 验收标准（BDD 场景）

```gherkin
功能: 会话进程面板

  场景: 命令进程登记与监控
    假如 会话 A 中 Agent 开始执行命令 "bun run dev"
    那么 进程面板出现一条 running 记录，显示命令摘要与运行时长
    并且 tab 徽标显示活跃进程数 1
    并且 当前激活 tab 不被自动切换

  场景: 终止长驻命令进程
    假如 会话 A 中存在 running 的命令进程 "bun run dev"
    当 用户点击「终止」并确认
    那么 该次工具执行被中断
    并且 记录状态变为 killed
    并且 消息流中对应过程块同步结束

  场景: 已退出进程保留
    假如 命令进程 "bun test" 以退出码 1 结束
    当 用户切换筛选到「全部」
    那么 列表中存在该记录，状态 exited、退出码 1
    并且 用户可展开回看其输出历史

  场景: 会话隔离
    假如 会话 A 有 2 条进程记录，会话 B 有 1 条
    当 用户从会话 A 切换到会话 B
    那么 面板只显示会话 B 的 1 条记录，徽标数随之更新

  场景: 终端跳转
    假如 会话 A 中 Agent 打开了终端 "dev-shell"
    当 用户在进程面板点击该终端记录的「在终端 tab 中打开」
    那么 右侧工作区切换到 terminal:{id} 独立 tab

  场景: 会话删除清理
    假如 会话 A 存在活跃终端与 running 命令进程
    当 用户删除会话 A
    那么 活跃进程被终止
    并且 会话 A 的进程记录被清理
```

测试实现遵循仓库 BDD 风格约定，覆盖以上正常路径与主要边界（并发同名进程、终端手动关闭联动、恢复场景不恢复记录）。
